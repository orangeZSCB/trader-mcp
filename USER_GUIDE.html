Trader MCP · 用户指南 · MMXXVI

交易,如代码
般严谨

Trader MCP 是一套为 AI 代理设计的交易工具集。它将每一笔交易视为一次代码提交——先暂存、再提交、最后推送至券商。这套看似繁复的流程,正是资金安全的最后一道防线。本指南将指引您与 AI 代理协作,安全、透明地执行每一笔交易。

贰 · Trade-as-Git 心法

每一笔交易都经历四个状态,如同 Git 中的代码变更。理解这套心智模型,是与 AI 代理有效协作的前提。

Fig. I — 交易状态机
i.
stage_*
将意图写入暂存区。券商对此一无所知。
→
ii.
commit
将暂存操作打包为命名提交,附上决策理由。
→
iii.
pending
等待用户审批。仍可撤销,零副作用。
→
iv.
push
不可逆。订单发送至券商,资金开始流动。
"暂存与提交是 AI 的自由;推送是人类的权力。" — Trade-as-Git 设计哲学

关键原则:在推送之前,任何操作都是可逆的,都不会触及真实资金。AI 代理可以在暂存区自由实验、调整策略,直到您明确授权推送。

肆 · 推送仪式

当 AI 代理准备执行交易时,必须遵循以下五步仪式。这是您与 AI 之间的契约,缺一不可。

  1. 带意图暂存

    AI 使用高级工具(placeOrder, modifyOrder 等)暂存操作,并传入 commitMessage 说明交易理由。差的理由:"买 AAPL"。好的理由:"入场:AAPL 突破 200 日均线;1% 组合风险;止损 195"。

  2. 展示待执行内容

    AI 调用 tradingStatus,将结果以表格形式呈现给您。永远不要依赖 AI 的记忆——必须以 tradingStatus 返回的实时数据为准。

  3. 请求明确授权

    AI 使用标准话术请求授权。等待您的回复。沉默、离题、部分回应都视为未授权。

  4. 根据回复分支

    · 明确同意("yes", "push", "确认", "推送") → AI 调用 tradingPush
    · 明确拒绝("no", "cancel", "取消") → AI 调用 tradingReject
    · 要求修改("改为 50 股", "限价 150") → AI 不推送,重新暂存后返回步骤 2
    · 回复模糊 → AI 提出一个澄清问题,不猜测

  5. 报告实际结果

    推送后,AI 展示提交哈希与券商响应。如有任何 success: false 的操作,必须逐字展示错误,不得掩盖部分失败。

⚡ 授权不延续

一次"yes"仅授权刚刚展示的特定提交。每次新推送都需要新的仪式。即使您在对话早期说过"好的,买 AAPL",AI 也不能在后续对话中以此为由直接推送——必须重新请求。

场景一:顺利路径

AI 已在 alpaca-paper 暂存(提交 a1b2c3d4,"入场:AAPL 回调至 175 支撑;风险定义限价单"):

# 操作 标的 数量 类型 价格 有效期
1 BUY AAPL 10 LMT 175.50 DAY

预估成本:~$1,755 (USD)。
账户购买力:$50,000。市场:开盘中(16:00 ET 收盘)。

推送至券商?回复 yes 执行,no 丢弃,或告知修改意见。
您 yes
AI 已推送。提交 a1b2c3d4 已生效。

· BUY 10 AAPL LMT 175.50 → 已提交,orderId xyz-789,状态 accepted。等待成交。

场景二:用户拒绝

您 不,价差太宽了

需要我放宽限价、切换为市价单,还是等待更窄的价差?

场景三:用户要求修改

您 改成 50 股,不是 10 股

陆 · 量化脚本

calculateQuant 工具接受 Python/pandas 子集脚本,对 K 线数据执行技术分析。与 v1 的 calculateIndicator 不同,v2 以 barId 为键,可精确指定数据源(特定券商的 K 线),或在同一脚本中混合多个数据源。

基本语法

脚本由一个或多个 name = bars(...) 绑定,后跟最终结果表达式:

# 获取 AAPL 250 日 K 线 s = bars("alpaca-paper|AAPL", "1d", count=250) # 计算 50 日与 200 日均线差 sma(s.close, 50) - sma(s.close, 200)

bars() 参数

  • barId:数据源标识,格式 {source}|{symbol}。券商 barId 如 "alpaca-paper|AAPL";数据供应商 barId 如 "yfinance|AAPL"
  • interval:K 线周期,"1m" "5m" "15m" "30m" "1h" "4h" "1d" "1w"
  • count=N:最近 N 根 K 线
  • asset=:数据供应商 barId 必填,"equity" | "crypto" | "currency" | "commodity"

可用函数

趋势/动量: sma, ema, rsi, bbands, macd, atr, roc, zscore, slope

成交量: rvol, obv, mfi, vwap

统计: stdev, max, min, sum, average, median, highest, lowest, correlation

💡 提示

指标函数直接返回最新值(标量),不要对其索引。只有原始列是序列,用 s.close[-1](最新)或 s.close[-n](倒数第 n)索引。

面板 · 批量计算

结果可以是字典 { "label": expr, ... } 或列表 [ expr, ... ],最多 50 项。用于多时间框架、多标的、多指标的一次性计算:

h1 = bars("binance-readonly|BTC/USDT", "1h", count=250) h4 = bars("binance-readonly|BTC/USDT", "4h", count=250) h12 = bars("binance-readonly|BTC/USDT", "12h", count=250) { "1h": rsi(h1.close, 14), "4h": rsi(h4.close, 14), "12h": rsi(h12.close, 14) }

返回: { "1h": 53.2, "4h": 48.9, "12h": 61.4 }

柒 · 八荣八耻

以下是 AI 代理在交易场景中必须避免的八种失败模式。这些不是假设——它们都曾在真实场景中发生过。

耻行为正确做法
以模糊执行为耻 未经明确"yes"就推送 暂存、展示、请求——缺一不可
以瞎猜接口为耻 连续调用 tradingPush 和 tradingCommit,事后才请求授权 授权在推送之前,永远不在之后
以臆想业务为耻 凭记忆描述暂存操作 暂存与请求之间必须重新调用 tradingStatus
以跳过验证为耻 隐藏券商错误 任何 success: false 必须逐字展示
以创造接口为耻 发明工具参数 Schema 即契约,不添加未定义字段
以盲目修改为耻 未先 getOrders 确认订单存在就调用 modifyOrder 先查询,再修改
以破坏架构为耻 将 commitMessage 视为 UI 字符串 它是审计日志条目,为未来的自己而写
以假装理解为耻 部分成交就报告"完成" 清点成交与拒绝,如实告知
